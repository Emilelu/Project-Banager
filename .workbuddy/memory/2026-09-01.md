  selenium-manager 联网下载 driver 失败（网络受限），该路线放弃。
- 改用方案：直接以「用户日常使用的 Chrome 便携版（`D:/Softwares/Daily/Chrome/App/Chrome.exe`，
  Data 目录自带 Dark Reader 4.9.129 扩展）」打开构建产物 dist/index.html 做端到端验证——
  验证即真实生产组合（Chrome + DR 插件 + GitHub Pages 部署后的单文件产物）。
- DR 源码机制确认（从已装扩展 inject/index.js 提取）：
  1. `canFilterImage(url)`：仅同源 URL 与 data: 才做图片滤镜；跨域（tc.alcy.cc 等）**不满足**→ 图不被反色/还原，但背景色会被 `modifyBackgroundColor` 重写；
  2. 含 `::before`/`::after` 的规则会把伪元素段**剥掉**再改属性——即 `body.with-bg::before { background: var(--bg-image)... }` 会被改造成直接命中 `body.with-bg` 的 background 规则；
  3. `getModifiedUserAgentStyle` 会注入 `html { background-color: <重写后的深色> !important; }`；
  4. 页面元素上挂 `data-darkreader-scheme` / `data-darkreader-mode` 属性可作检测锚点。
- 结论：根因确认——DR 动态模式把含 `::before`/`::after` 的规则**剥掉伪元素段再改写**（`body.with-bg::before` 被改写成命中 `body.with-bg`），伪元素壁纸层整条丢失；且跨域图片不在 `canFilterImage` 还原范围。

## 方案推翻：回退 DR 元素化，改用官方 darkreader-lock（用户提供文档）
- 用户不满（合理）：改 `<img>` 引入淡入回归、改来改去问题更多。用户查 DR 官方文档发现
  **官方支持的「Dark Reader lock」**——`<meta name="darkreader-lock">`（head 内），或 JS 动态
  `document.createElement('meta'); lock.name='darkreader-lock'; document.head.appendChild(lock)`，
  站点声明后 DR 整站禁用。
- 执行：`git revert a9cec6b`（撤销等图片就绪改动）→ `git revert 613189a`（撤销 `<img>` 元素化）。
  壁纸层回到 DR 适配前（e76254c 之后）的伪元素方案：`body.with-bg::before` 壁纸 + `::after` 遮罩 +
  `--bg-image` CSS 变量。加载动画（bg-reveal 0.4s 淡入 + bg-focus 聚焦模糊）随之恢复。
- 加锁：`index.html` `<head>` 静态 `<meta name="darkreader-lock">`（注释说明原因：应用自带 .dark 深色
  模式、壁纸用伪元素，DR 会剥 ::before/::after 导致壁纸消失，故整站禁用）；`main.js` 顶部再动态
  appendChild 一次兜底（DR content script 在 document_start 注入，可能早于静态 meta 解析）。
- 产物断言（实质 11/11）：CSS minifier 会把 `::before/::after` 压成单冒号 `:before/:after`——
  断言要查单冒号形态；`--bg-image`/`with-bg`/`bg-reveal`/`bg-focus` 全在、`bg-wallpaper`/`bg-scrim`
  元素零残留；静态 + 动态 darkreader-lock 都在；CORS crumb 与 bgAutoSwitch 默认 true 回归锚点过。
- 教训：DR 兼容的正解是**官方 darkreader-lock 整站禁用**（应用自带深色模式时最干净），而不是猜 DR
  改写规则去适配。遇插件改写类问题先查官方文档的禁用/豁免机制。壁纸层继续用伪元素 + CSS 变量（无 DR
  干扰时动画/淡入/聚焦一切正常）。
