## 壁纸模块三项修复（固定壁纸失效 / 浅色文字对比度 / 自定义壁纸交互）

### 1. 固定壁纸失效 — 根因与解法
- 根因：`t.alcy.cc/ycy` 是随机端点（301→302→`tc.alcy.cc/tc/<date>/<hash>.webp`）。
  最终 CDN 图片**不回** `Access-Control-Allow-Origin`，所以 `fetch()` 默认 cors 模式会在
  最后一跳被浏览器拦成 TypeError — 之前那版"解析重定向"的代码其实永远走 fallback，
  存下来的仍是随机端点，重开页面自然换图。
- 实测结论（curl + Firefox/selenium 实测）：
  - `fetch(url, {mode:'no-cors'})` 在 **Firefox 下 response.url 为空串**，Chrome 才可能保留最终地址
    → 只能当兜底，不能当主路径。
  - **正解**：Alcy 有地址接口 `https://t.alcy.cc/ycy?json=true`，直接返回最终图床 URL
    （text/plain，全程 `ACAO: *`），浏览器可正常读取。这是「固定壁纸」能生效的关键。
- 落地：新增 `PROVIDERS` 配置（每源有 entry 随机端点 + api 地址接口）+ `resolveStableUrl()` 三级降级：
  ① api 地址接口 → ② fetch 跟随重定向取 response.url → ③ no-cors 跟随重定向 → 失败回退随机端点。
  另加 `migratePinnedEndpoint()`：启动时若已持久化的 bgUrl 仍是随机端点，自动重新解析一次。

### 2. 浅色模式文字对比度
- 没有改模板里的 class 名，而是在 `style.css` 里加裸选择器覆盖（`.text-gray-300/400/500`
  放在 `@tailwind utilities` 之后）。原因：改 class 名会连带改动 `.dark .text-gray-*`
  覆盖规则的作用对象，破坏深色模式。裸选择器权重 (0,1,0) 低于 `.dark .text-gray-*`(0,2,0+important)
  与 Tailwind hover 变体(0,2,0)，因此只影响浅色、不碰深色、不破坏 hover。
- 映射 300→500(#6b7280)、400→600(#4b5563)、500→700(#374151)。
- 副作用修补：基线下调后 `text-gray-500 hover:text-gray-700`、`text-gray-400 hover:text-gray-600`
  会撞色，补了 `html:not(.dark) .hover\:text-gray-600/700:hover` 两条规则把 hover 再压深一档。

## 第三批（4 项）动画/菜单/取色修复
- **backdrop-filter 的坑（重要）**：按 Filter Effects 规范，`opacity<1` 的元素会形成
  backdrop root，其后代的 `backdrop-filter` 只能采样到"组内"内容（几乎为空）。
  因此把 `opacity` 放在**祖先**上做过渡，内部毛玻璃的模糊会被吞掉、动画结束才突然出现。
  修法：`.fade-*` 与 `.modal-*` 只保留 `transform`（transform 不形成 backdrop root），
  遮罩层 `modal-overlay` 仍可淡入（元素自身的 opacity 不影响自身的 backdrop-filter）。
- 右键菜单遮挡：新增 `src/composables/useContextMenu.js`，渲染后用 `offsetWidth/offsetHeight`
  量尺寸（布局尺寸，不受 scale-in 的 transform 影响；`getBoundingClientRect` 会返回缩放后的
  尺寸导致误判），下方/右侧不足时翻转。三个视图共用。
- 文字色按壁纸动态计算：新增纯函数模块 `src/composables/colorMath.js`（无 DOM 依赖，可在 node
  下直接测）。流程：采样分区亮度（左侧 18% 竖条=侧边栏，整幅=内容区）→ 叠加遮罩/玻璃算出
  实际背景亮度 → 按目标对比度反推 g500 → g400/g300 沿用现设计亮度倍率 → 二分调 HSL 的 L
  保留原 slate 色相。写入 `--tx-300/400/500` 与 `--sb-fg`，无壁纸时移除内联变量回落到固定色。
- 踩坑：HSL→RGB 的分量本身已是 sRGB 编码值，**不能**再过 gamma 编码（我一开始误用
  `linearToSrgb`，导致基准色复现成 `59 65 72` 而非 `55 65 81`，且色相偏掉）。

## 用户反馈"打不开页面"——排查结论（非入场动画）

  - 能开 → 与壁纸/入场相关（保险已兜底）；

## 自定义图片地址导致页面卡死 + 动效三项微调

用户反馈：自定义图片地址 → 页面打不开（浏览器转圈、随后无响应）；随机壁纸正常；此前 `?nobg` 也打不开。

### 根因定位
- 随机壁纸走 `bgAutoSwitch=true`，**不执行** `startupSharpen()`；自定义（固定）地址走 `bgAutoSwitch=false`，**会执行** `startupSharpen()`。
  两路几乎共用同一 init，唯一差异即此处 → 卡死锁定在自定义（固定）壁纸的启动入场路径。
- `startupSharpen` 给 `body` 加 `bg-focus`，其 `::before` 动画 **同时**动 `filter:blur()` + `transform:scale()`。
  全屏 `filter:blur` 在 `file://` 下对一张遥不可及的自定义大图**逐帧重栅格化**，拖垮渲染、标签页"无响应"。
  此即"转圈 → 无响应"的真正来源（setTimeout 保险因主线程被卡也来不及触发）。
- `?nobg` 旧正则 `/[?&]nobg/.test(location.search) || /#.*[?&]nobg/.test(location.hash)` 只认 query 里的 `?nobg`，
  用户多半用 `dist/index.html#nobg`（hash 形态）或带 hash 的 URL → 正则不匹配 → 逃生通道没生效 → 入场照跑 → 卡死。
  这解释了为什么上一轮用户说"`?nobg` 也打不开"。

### 处理
- **启动入场改 transform-only**：新增 `body.with-bg.bg-boot::before{transform:scale(1.13)}`（仅位移，合成器独占、零重栅格化），
  `startupSharpen`/`clearBootFocus`/focus 观察器/3s 保险 全部由 `bg-focus` 改用 `bg-boot`。
  弹窗聚焦仍用 `bg-focus`（含 `filter:blur` 加深）—— occasional，随机壁纸下已验证不卡。
- **逃生通道修正**：`?nobg`/`#nobg`/`&nobg` 任意形态均生效（`/[?&#]nobg\b/`）；新增 `?reset`/`#reset` 直接 `localStorage.removeItem` 清掉坏配置（含会卡死的自定义地址），按默认值重启。
- **关闭曲线与打开严格一致**：`.modal-leave-active` / `.modal-overlay-leave-active` 由 `--dur-motion-close(0.35s)` 改为 `--dur-motion-open(0.38s)`，
  与 `.modal-enter-active` 同曲线 `--ease-motion`、同时长，消除开合节奏割裂。
- **页面切换更丝滑**：`.fade` 由 `0.3s`+`translateY(8px)` 改为 `0.4s`+`cubic-bezier(0.4,0,0.2,1)`+`translateY(14px) scale(.992)`，
  仍只动 transform（保留 backdrop-root 修复），非线性 S 曲线更长更柔。

### 入场动画"始终不生效"根因与修复（续）

## 跟随壁纸取色失效 + 关闭弹窗缩放 + 刷新淡入 + 自定义壁纸卡顿（commit bf4abf3 / 72972db / b9ac37a）

### 跟随壁纸取色失效（bf4abf3）
- 根因（curl 实测）：上一轮 `resolveStableUrl` 修正后 `state.bgUrl` 变成**稳定图床地址 `tc.alcy.cc/tc/...webp`**，它**不返回 CORS 头**（仅 `HTTP/1.1 200`）；而取色 `extractPaletteFromImage` 用 `crossOrigin="anonymous"`，直连必失败。代理链里排第一的 `images.weserv.nl` 对 tc.alcy.cc 实测返回 **400**，只有 `proxy.cors.sh` 返回 200 + ACAO:*。
- 修法：`CORS_PROXIES` 重排——cors.sh 置顶（实测可用）、allorigins 第二、weserv 兜底。

### 关闭弹窗缩放过快（bf4abf3）
- 需求：关闭弹窗时壁纸缩放幅度/时长要与打开一致（0.8s 缓动），不要 0.25s 快进。
- 修法：移除 `modal-closing` 类（JS toggle + CSS `body.with-bg.modal-closing::before` 0.25s 覆盖）；**保留** `hasClosingModal()` 早检测，让 bg-focus 在关闭过渡一开始就摘掉，壁纸缩放用与打开一致的 0.8s 缓动回桌面态。

### 刷新时正在追番无淡入（72972db）
- 修法：App.vue 的 router-view `<transition name="fade" mode="out-in">` 加 `appear`，让初始挂载也播放 fade 入场动画。

### 自定义壁纸下弹窗卡顿（b9ac37a）
- 修法：ThemeSettings 预览 `<img>` 加 `loading="lazy"` + `decoding="async"`，大图异步解码，避免阻塞弹窗渲染。

### 验证
- 构建 1,589.42 kB。bundle 断言：modal-closing 已移除、cors.sh 置顶、weserv 兜底、transition appear、`loading:"lazy"`/`decoding:"async"`（Vue 编译为对象属性）、0.8s 打开基线保留、bg-focus 16px blur 保留。
