### 实测结论：键盘不可达的控件

| 页面 | Tab 实际可达 | 交互控件清单 | 主要缺口 |
|---|---|---|---|
| 追番 `WatchingView` | 13 | 55 | **全部追番卡片本体不可达**（`div.watching-card` 无 `tabindex`/`role`），选中、批量勾选、双击进编辑全部只能靠鼠标；操作面板 6 个按钮因 `:disabled` 未选中而跳过（属预期）；卡片内 `+` / `-` 可达 |
| 等番 `RemainingView` | 11 | 36 | **两个可排序表头不可达**（`th` 仅 `@click`，无 `tabindex`/`role`，读屏拿不到 `aria-sort`）；**行勾选框不可达**（纯 `div`，无 `role`/`tabindex`）；表体行选中不可达 |

### 实测结论：弹窗

```
修复前：
  role=null  aria-modal=null  aria-labelledby=null
  焦点进弹窗：true（因为页面自己调了 focusNameInput）
  Esc：能关（页面级 document keydown）
  关闭后焦点：BODY ← 丢失，触发按钮拿不回来
```

即：三个页面各有 `document.addEventListener('keydown', handleKeydown)` 处理 Esc，但**没有任何焦点归还逻辑**，也没有 Tab 陷阱——焦点可以 Tab 到遮罩背后的内容。这是本次最实质的无障碍缺陷。

### 3. 所有 `.app-dialog`：`role="dialog"` + `aria-modal="true"` + `aria-labelledby`，打开聚焦首输入、Esc 关闭、关闭归还焦点

**新增复用组合式** [useDialogFocus.js](src/composables/useDialogFocus.js)（约 150 行）：

- `collectFocusable(root)`：按 DOM 顺序返回弹窗内可聚焦元素（`a[href]` / 可用 `button` / `input` / `select` / `textarea` / `tabindex≠-1`）
- `firstField(root)`：优先首个输入类控件，没有则退回首元素
- `focusFirst()`：打开时聚焦（优先 `initialFocus`，其次 `firstField`）
- `restore()`：关闭后按「触发控件 → 页面根节点」两段回退
- `Tab` / `Shift+Tab` 在弹窗内循环；焦点跑到弹窗外时按 Tab 拉回
- Esc 默认**不接管**（三页已有 `document` 级 `handleKeydown`，且有「关弹窗顺带退批量模式」的语义，重复接管会一次按键关两层）；`onEscape` 交由无页面级处理的弹窗使用

### 6. 额外：追番卡片本体键盘可达

实测暴露的最大缺口——追番页每张卡片是一个纯 `div`，键盘完全进不去。补 `role="button" tabindex="0" aria-pressed` + `aria-label`，`Enter`/`Space` 触发选中/批量勾选。

关键细节：卡片内含行内编辑输入框与 `+`/`-` 按钮，所以键盘处理走 `onCardKeydown`，**只在 `e.target === e.currentTarget` 时响应**——否则在名称框里打空格会被卡片的 `preventDefault` 吞掉，回车保存也会顺带切选中。

## 五、遗留项

1. **表体行选中（`tr` 点击选中）仍只有鼠标路径**。等番/已看页的 `tbody tr` 有 `cursor:pointer` 与 `@click`，但没有 `tabindex`/`role`。若补 `tabindex="0"`，一行 4–5 个单元格全部可点（`td` 继承 `cursor:pointer`），Tab 序会急剧膨胀（48 条数据 × 5 列）。**建议做法**：只给行加 `tabindex="-1"` + 键盘上下键移动焦点的「roving tabindex」方案，或把「选中」抽象到工具栏按钮上。这属于交互设计决策，需要产品确认，本次未擅自改动。追番页的等价能力已通过卡片本体 `role=button` 补齐。
2. **分页「上一页 / 下一页」在首页/末页因 `:disabled` 从 Tab 序消失**，属标准行为，未改。
3. **`ThemeSettings` 与 `App.vue` 导入确认弹窗的焦点管理未纳入 `a11y.test.js`**：两者在既有测试里被 `stubs: { ThemeSettings: true }` 桩掉，或依赖 router 上下文，单测接入成本高于收益；已用 Playwright 实测覆盖（`app-dialog` 语义与 Esc 归还均验证）。`dialog-focus.test.js` 已覆盖组合式本体行为。
4. **`context-menu`（右键菜单）仍只支持鼠标**。它不是弹窗（无遮罩、无 `aria-modal`），本次按「`.app-dialog`」范围未纳入。若要键盘可达，需要「Shift+F10 唤起 + 方向键导航 + Esc 关闭」一套，是独立工作量。
5. **`Toast` 的 `aria-live` 已具备**（前一轮修的 `role=status aria-live=polite aria-atomic=false` + 单条关闭按钮 `aria-label`），本次复核无需改动。
6. **未做读屏实机验证**（NVDA / VoiceOver）。本次以属性语义 + DOM 顺序 + 焦点轨迹为依据。`aria-sort` 在 `th` 上属于「`role=button` + `aria-sort`」的非标准组合（严格来说 `aria-sort` 应用于表头单元格，而表头单元格不该同时是 button）；当前实现让 `th` 同时承担两者，读屏能播报但语义略混。若后续要严格对齐 WAI-ARIA，可改为「`th` 保留 `aria-sort`，内部再放一个 `<button>`」，代价是模板与测试都要改。**当前形态可用，未擅自重构。**
